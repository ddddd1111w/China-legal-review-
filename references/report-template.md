## 1. 合法性审查意见书（通用）

```
合法性审查意见书

编号：【】
送审单位：【】
审查事项：【对××文件/××行为的合法性审查】
收审日期：【】

一、审查依据
（一）《××法》（制定机关，×年×月×日施行）第×条第×款第×项；
（二）《××行政法规》……；
（三）……
（依据按效力位阶自高至低排列，均为现行有效文本）

二、审查范围与材料
1. 本次审查对象：【文件名/行为名称及文号】
2. 已收到的材料：【清单】
3. 未提供、需补充的材料：【清单；无则写“无”】
（说明：本意见仅就合法性发表意见，合理性、可行性问题另列建议；不属本文库核验范围的地方性法规、规章、规范性文件，以送审方提供文本为准。）

三、审查情况
（一）【审查点1，如：主体与权限】
  查明事实：……
  法律依据：《××法》第×条：“……（原文要点）”
  比对意见：【符合/不符合/无依据/依据冲突】，理由：……
（二）【审查点2，如：程序】
  ……
（三）【审查点3，如：内容与裁量】
  ……

四、审查结论
【总体结论，使用五级口径之一：合法 / 不合法 / 部分不合法 / 存在法律风险（依据不足）/ 无法判断（待补充）】
【若为部分不合法或存在风险，逐条列明：问题条款→违反依据→理由】

五、处理建议
1. 【针对违法点的具体修改/撤销/补正/重新履行程序建议】
2. 【风险防范建议】
3. 【需提请有权机关裁决/备案审查的，写明机关与路径】

审查人：【】　　复核人：【】　　日期：【】
```

## 2. 行政规范性文件合法性审核意见

```
关于《××（送审稿）》的合法性审核意见

一、文件基本情况
  起草单位：　　文号：　　拟发文主体：
  制定背景与拟解决的主要问题：

二、审核过程
  【征求意见、评估论证、部门会签等情况】

三、合法性审核情况
（逐项给“合法/不合法/无依据”的明确意见）
1. 制定主体：……
2. 制定权限：是否存在违法设定行政许可、行政处罚、行政强制、
   行政征收、机构编制经费，是否违法增加义务、减损权利或增加本机关权力。
3. 制定程序：征求意见、合法性审核、集体审议、公开发布等。
4. 文件内容：与上位法及同位阶文件是否抵触；措施是否有授权依据；
   市场准入与公平竞争、有效期与施行日期、解释主体等。

四、审核结论
  【审核通过 / 审核不通过（列明违法条款及依据）/ 建议修改后再审（列明修改清单）】

五、修改建议（逐条对应问题条款，给出可直接替换的合法表述方向）
```

## 4. 法律咨询答复（B类任务）

```
【问题】一句话概括。

【结论】先给直接、明确的答案；存在多种可能的，按事实假设分别给结论。

【依据与分析】
1. 法律关系定性：……
2. 法律依据：
   - 《××法》第×条第×款（×年×月×日施行）：“……”
   - 《××司法解释》第×条：“……”
3. 要件涵摄：事实要件与法律要件逐项对照。
4. 不同观点/争议（如有）：……

【操作建议】
1. 程序、管辖、时效、所需材料；
2. 救济途径与期限（期限数字以文库原文为准）。

【提示】信息不足之处、需进一步核实的事实、文库未收录的依据。
```

## 5. 条文引用著录规范

- 首次引用写全称并标注：`《中华人民共和国××法》（20××年×月×日施行）第×条第×款第×项`；其后可简称《××法》。
- 引用原文加引号并保持与文库文本逐字一致，不得凭记忆改写；条文较长可摘引要点，但不得改变规范含义。
- 修正案、法律解释、决定单独引用时写其自身名称与日期。
- 司法解释写全称与制发机关（最高人民法院/最高人民检察院）。
- 同一问题有新旧文本时，注明适用的文本及理由（见 conflict-rules.md 第 5、6 节）。
- 文库未收录的位阶（地方性法规、规章、地方规范性文件）必须注明“未在本文库核验，以送审文本/官方公布文本为准”。
```
