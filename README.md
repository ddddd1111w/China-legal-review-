# legal-review · 法律法规文库检索与合法性审查 Skill

一个面向 LLM Agent 的**自包含法律技能（Skill）**：内置国家法律法规数据库现行有效文本，让模型在回答法律问题、做合法性审查时，**先检索原文、再引用条文、最后下结论**，而不是凭记忆"背法条"。

- 内置 **1514 篇**现行有效法规（宪法 7、法律 340、行政法规 604、监察法规 2、司法解释 561），约 **751.5 万字**
- 纯 Python 标准库实现，**零第三方依赖**，复制即可用
- 文库可随时**新增 / 替换 / 删除**，一条命令增量重建索引
- 路径自适应：整个文件夹复制到任意电脑、任意目录均可运行，不写死绝对路径
- 与具体模型无关，已在 **DeepSeek**、**智谱 GLM** 等通过 DSH（DeepSeek Harness）接入的模型上使用

## 它能做什么

1. **合法性审查 / 法制审核**：对规范性文件、红头文件、行政行为、执法决定、行政处罚/许可/强制案件、合同、制度文稿，按"主体·权限·程序·事实·依据·内容·形式"七维度逐项比对法条，给出五级结论（合法 / 不合法 / 部分不合法 / 存在法律风险 / 无法判断）并套用审查意见书模板。
2. **法律问题咨询**：按"定法 → 定条 → 读原文"检索，给出结论、依据链（法名＋条号＋原文要点＋施行日期）与风险提示，自动处理效力位阶、新旧法、特别法、溯及力等冲突规则。
3. **条文检索与核对**：标题查找、全文关键词检索、按条号精读、版本比对，所有结论都可回溯到本地原文。

模型被要求**只引用从文库中实际检索到的条文原文，严禁凭记忆引用法条**。

│   ├── legal_common.py       # 共享路径解析（自动定位文库）
│   ├── convert_doc.ps1       # 旧版 .doc 转 .docx（调用本机 Word/WPS，仅 Windows）
│   └── library_config.json   # 文库位置配置（默认指向自带的 library/）
├── references/               # 模型按需加载的方法论与模板

│   ├── conflict-rules.md     # 效力位阶、新旧法/特别法、冲突裁决、溯及力
│   └── report-template.md    # 审查意见书 / 法制审核意见 / 咨询答复模板
└── library/                  # 自带文库（自包含，开箱即用）
    ├── 01-宪法/ … 05-司法解释/   # 原始 Word 文本（.docx/.doc，唯一数据源）
    ├── _manifests/final_manifest.json  # 官方元数据（公布/施行日期、制定机关等）

        ├── library-map.md       # 分类导航
        └── <分类>/*.txt         # 每部法律一个带元数据头的纯文本

## 安装

本 Skill 面向 [DSH（DeepSeek Harness）](https://www.deepseek.com/) 的文件系统技能机制，加载器会扫描技能根目录下的 `<技能名>/SKILL.md`，并通过文件监视**热发现**，新增技能无需重启。

1. 下载 / 克隆本仓库，得到 `legal-review` 文件夹（保持文件夹名不变）。
2. 把整个 `legal-review` 文件夹放进 DSH 的技能根目录：
   - **Windows（默认 DSH_HOME）**：`%USERPROFILE%\.dsh\skills\`
   - **Windows（自定义 DSH_HOME，如 `D:\ai\.dsh`）**：`D:\ai\.dsh\skills\`
   - **macOS / Linux**：`~/.dsh/skills/`
   
   即最终路径形如 `...\.dsh\skills\legal-review\SKILL.md`。
3. 环境要求：Windows / macOS / Linux 上装有 **Python 3.9+** 并可在命令行调用 `python`。解析 `.docx` 无需任何第三方包；仅当需要收录旧版 `.doc` 时，Windows 下调用本机 Word 或 WPS 自动转换。
4. 自带文库已包含生成好的 `_text` 索引，**开箱即用，无需先跑同步**。

用 Git 安装（便于后续 `git pull` 更新）：

```bash
cd <你的-skills-目录>
git clone <本仓库地址> legal-review
```

## 快速开始

在 DSH 网页端 / 客户端中：

- **自动触发**：直接提出任务，例如
  - “帮我审查这份行政处罚告知书的程序是否合法”
  - “行政拘留要不要告知听证权？依据第几条？”
  - “这份规范性文件能不能设定罚款？”
  
  模型会自动加载本技能，调用检索脚本并引用原文作答。
- **手动触发**：输入 `/legal-review` 强制启用。
- **切换模型**：在 DSH 模型选择处切换 DeepSeek、智谱 GLM 等即可，技能逻辑与模型无关；若某模型不可用，先在 DSH 设置中配置对应服务商的 API Key。

首次可让模型运行 `status` 确认文库就绪（把 `<SKILL>` 替换为技能实际所在绝对路径，即加载时给出的 Base directory）：

```powershell
python "<SKILL>\scripts\search_law.py" status
```

## 检索命令速查

所有命令均在 `scripts/` 下，用 Python 运行；路径含中文请加引号。

| 目的 | 命令 |
|---|---|
| 文库状态 / 统计 | `python search_law.py status` |
| 按名称找法律 | `python search_law.py titles 行政处罚` |
| 查看元数据 / 版本 | `python search_law.py info 行政处罚法` |
| 全文检索条文 | `python search_law.py search 听证 行政拘留` |
| 读某条原文 | `python search_law.py get 行政处罚法 --article 63` |
| 读结构与预览 | `python search_law.py get 行政强制法` |

常用参数：

- `titles` / `search`：`--cat 02-法律` 限分类、`--all` / `--all-versions` 含旧版、`--limit N`
- `search`：多关键词默认“且”，`--any` 改“或”，`--law 治安管理处罚法` 限定某部法，`--regex` 正则
- `get --article`：支持 `63`、`六十三`、`63-65`（范围）、`9,44,63`（逗号/顿号多段）

## 更新文库：新增 / 替换 / 删除法规

原始 Word 文件是**唯一数据源**，`_text` 与索引全部由脚本生成。设计上支持随时增量更新：

1. **新增**：把 `.docx`（或旧版 `.doc`）放入 `library/` 下对应分类目录。文件名建议 `法律全称_公布日期yyyyMMdd.docx`（如 `中华人民共和国XX法_20260101.docx`），脚本据此解析标题与日期，并标注〖补充〗提示人工核对。
2. **替换为新版**：把新版 Word 放入分类目录（同名覆盖或新日期文件名均可）；脚本按公布日期自动归组，检索默认只返回最新版，旧版保留并标记【旧版】可追溯。旧版若已失效，直接删除其源文件即可。
3. **删除**：从分类目录删除对应 Word 源文件。
4. 运行增量同步（仅处理新增 / 变更 / 删除，通常几秒完成）：

   ```powershell
   python "<SKILL>\scripts\sync_library.py"
   ```

   - 全量重建加 `--full`；跳过旧版 `.doc` 加 `--no-doc`。
   - 同步会自动：抽取正文、写入元数据头、同法新旧版本归组、重建 `index.json` / `titles.json` / `library-map.md`、清理已删除源文件对应的文本。
5. 同步完成后即可检索，**无需重启 DSH**；不要手工编辑 `_text` 内文件（下次同步会被覆盖）。

> 也可以直接让对话中的模型帮你做：把法规文件发它并说“加入法律文库后同步”，模型会放置文件并运行同步脚本。

## 使用 skill 外部的文库

默认使用技能自带的 `library/`（自包含、零配置）。若希望把更大的文库放在技能外部（例如网盘或数据盘），三种方式任选，优先级从高到低：

1. 同步时临时指定：`python sync_library.py --root "D:\其它\法律文库"`；
2. 设置环境变量 `LEGAL_REVIEW_LIBRARY` 指向文库根目录（对检索与同步同时生效）；
3. 编辑 `scripts/library_config.json`，把 `library_root` 改为文库绝对路径（相对路径则相对技能根目录解析）。

外部文库需包含同样的 `01-宪法` 等分类目录；首次使用先运行一次 `sync_library.py` 生成 `_text` 与索引。

## 工作原理

- `.docx` 用 Python 标准库 `zipfile` + `xml.etree` 直接解析 `word/document.xml`，无需安装 python-docx；旧版 `.doc` 在 Windows 下经 `convert_doc.ps1` 调用 Word / WPS COM 批量转换。
- 每部法规范文切成“章标题 + 条文”结构，以行首“第X条”（兼容“第X条之一”）为条头，并跳过开头目录，保证条号定位准确。
- 同标题法规按公布日期归组并标记最新版；检索默认只查最新文本，审查历史行为时可显式包含旧版。
- `legal_common.py` 以脚本自身位置锚定技能根目录，再按 `--root` → 环境变量 → 配置 → 自带 `library/` 的顺序定位文库，因此整个技能文件夹可任意移动 / 复制。

## 数据来源与时效

- 文本来源：国家法律法规数据库 <https://flk.npc.gov.cn>，采集口径为“现行有效”，采集日期 **2026-09-27**。
- 元数据（法律性质、制定机关、公布 / 施行日期）取自官方清单 `_manifests/final_manifest.json`；清单外用户自行补充的文件由文件名解析并标注〖补充〗。
- 法律会被修订或废止，**内置文本可能滞后**。正式使用前，请通过官方渠道核对所引法规是否仍为现行有效版本，并按上文“更新文库”流程替换新文本。

## 能力边界与免责声明

- 内置文库**仅含国家级文本**（宪法、法律、行政法规、监察法规、司法解释），**不含地方性法规、部门规章、地方政府规章及各类规范性文件**；审查对象引用这类依据时，需另行提供官方文本，模型会明确标注“不在文本库核验范围”。
- 本技能是**检索与辅助分析工具**，输出不构成法律意见，不能替代执业律师或法制部门的正式审核。审查意见一般不直接宣告文件 / 行为无效，而是指出冲突与依据，提出纠正、撤销、补正、重新履行程序或提请有权机关处理的建议。
- 因使用本技能产生的任何后果，由使用者自行承担。
